## 原生训练、读出和评价

- 使用 LEFT 官方提交 `3fadb4811797075e233076b9faceb0d8ec59b697` 的 SWaT 配置。31 通道、窗口 192、批量 128、Adam 初始学习率 `1e-4`、`type1` 日程、上限 20 轮、早停耐心 3。作者代码在前 495,000 个正常点拟合 StandardScaler，涵盖训练 `[0,396000)` 和验证 `[396000,495000)`。训练窗口步长为 1，验证和测试步长为 192。论文以非重叠协议描述结果，发布训练脚本实际使用重叠训练窗。 [发布实现](https://github.com/DezhengWang/Left/tree/3fadb4811797075e233076b9faceb0d8ec59b697)
- 测试区间 `[495000,944919)` 共 449,919 点。原生 `model.infer` 输出 2,343 个完整窗口内的所有位置，逐通道均值后按原序展平，共 449,856 个评分点，其中 54,621 个异常点。尾部 63 点无完整窗，无评分。发布 SWaT 配置使用 `alpha_cycle_s=0`、`alpha_ms_s=1` 和原生多尺度 SmoothL1 读出。论文评分公式给出一般形式，本次采用固定发布配置和实现。
- 原生全窗离线读出可使用被评分位置之后、同一窗口内的观测。原始归档首版的 `available_index` 误填为逐点索引，正确可用时刻是该窗口末点。逐点指标只依赖正确的 `absolute_time_index`。公开实现已纠正可用时间字段，首版原档保留。
- VUS 使用固定官方 `ts_ad_evaluation/auc_vus/metrics.py` 的 `metricor.RangeAUC_volume_opt`，`windowSize=100`、`thre=250`。点级 AP 使用 `average_precision_score`。梯形 AUC-PR 使用 PR 曲线的梯形积分，与发布脚本命名为 `AUC_PR` 的 AP 字段分别报告。测试标签仅在分数封存后用于评价。本轮未运行发布脚本的测试最优 F1 阈值路径，也未补原生阈值指标。

## 成本、复算与结论

一次 A40 作业按原早停规则在第 17 轮结束，共 52,581 次更新；正常验证损失选中第 14 轮、第 43,302 步，损失 `0.01870206855237484`。训练及推理实际占卡 3,892.672 秒，即 1.081298 GPU 小时，训练峰值分配约 1.445 GiB。主评价和独立复算各用 CPU 29.213 秒和 23.45 秒。AP 和两项 VUS 完全一致，ROC-AUC 和梯形 AUC-PR 的复算差异为 `1.11e-16`。
