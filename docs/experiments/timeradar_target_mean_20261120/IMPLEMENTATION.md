# Target-mean reconstruction in the fixed native TimeRadar R path

Only the target half's learning objective changes. Each source window retains the native ten-copy full-window MSE. Each target window uses the full100×C MSE of the differentiable mean of ten reconstructions. Both halves retain32 B1 windows, with each window loss divided64 before accumulation and a single AdamW step. There is no additional factor0.5, detach, teacher, new module or new score.

Writing `E=mean((mean_j(yhat_j)-x)^2)` and `V=mean(var_j(yhat_j, correction=1))` over all100×C entries, ten-copy MSE equals `E+0.9V`. For the same R batch and weights, the old minus new loss is `0.45*mean(V_T)`. CPU and real normal-window CUDA gates check both scalar and gradient identities. Training computes E directly; it never subtracts large losses to obtain the target objective. E_T,V_T,E_S,V_S are archived from the same forward that supplies gradients.

The shared `native_v_replay` entry has an optional `target_mean_source_copy` profile; its default native path retains its original calculations. New preparation byte-copies the accepted per-domain TASK, SCALER and PLAN. No resampling, source training, old inference or old metric recomputation occurs. Official initialization, frozen/eval backbone and order network, decoder-only gradients through inverse FRFT, fixed84551 complementary masks, B1 order semantics and all optimizer settings remain unchanged.

Exactly two endpoints are sealed in `ALL_MODELS_FROZEN.json`. The cache helper accepts this explicit barrier name; the previous six-model barrier remains its default. Each new endpoint receives independent CAL and QUERY native forwards on the old axes. The score remains original terminal99 nativeV, correction1 and channel mean, with canonical FP64 casting only. Four merged banks, ten readout jobs, source/checkpoint/runtime hashes and actual occupied GPU times are retained; labels are opened only after the final bank seal. Full checkpoints include official weights and remain outside Git.
