# Controlled-mechanism sidecar: engineering candidate

`hybrid_tsad.hybrid_v1.controlled_mechanism` adds no model, objective, calibration
fit or scientific scoring rule. It binds a separate root CPU-L0 operation and
calls the original SHA-verified frozen `cli.load_model`, `data.arrived_window`,
`training.tensor_batch/passes/iter_infer`, `scoring.residual_components` and
`apply_calibration`. A separate import namespace prevents a working-tree kernel
from silently replacing a frozen one. No old 13/23/24-file snapshot is edited.

`generate_pair` implements only the three predeclared technical L0 N/A pairs.
All latent seeds use family/role/integer run/stream; output names N/A never enter
the seed. Values/observed are returned separately from truth/latent/labels. Self
recursion remains continuous after changing back to the original delay, so its
recovery is not described as identical to normal. No circular roll or target
normalization fit is used. The other controls listed in the candidate mechanism
protocol (IRR/SB/normal variable lag, C2 signs, strong shift) are future scope,
not secretly generated by this technical L0 or claimed implemented here.

Default CLI is preview. `--execute --preflight-only` requires a new exact root
forward release and checks config/source/fresh metadata without opening PT or
Torch. The engineering-only release cannot execute a model. Actual CPU-L0 needs
the same exact gate, the original accepted checkpoint/calibration bytes and
explicit `CUDA_VISIBLE_DEVICES=''`, under an externally bounded owned CPU
supervisor. No retry, SSH, downloads, training or scientific metrics are launched
by this module. The example remains ROOT_PENDING and has unbound public asset
paths; it cannot authorize anything.

For the later separately approved L0, only six direct points are computed: N/A
for weak C1, Self C1 and mixed-sign Cross C3, each t2048. The seventh point is
Cross/N through original `iter_infer(index_plan=[exact singleton2048])`, never a
scan from t512. One `next` followed by immediate `StopIteration` is required.
Observation wrappers count 7 forecast, 7 reconstruct and 17 internal encodes;
they restore the exact instance-method lookup even on failure. Direct calls are
in eval/no_grad; exports only detach/CPU/copy already returned tensors. Every
point saves the full existing axes.lag, masks, stats and endpoint/scalar results.
No extra forward obtains a route and no route is added to the primary score.

The reference replays the direct point's pre-call Torch/NumPy/Python RNG state,
checks numerical/mask/index/seed and post-call RNG parity, then restores the main
six calls' final RNG even on failure. Original forward may itself advance RNG;
the claim is no extra perturbation from export/instrumentation, not an invented
claim that original forward never changes RNG. Model-state identities and source
checkpoint SHA are checked before/after. Partial direct bundles and final status
survive failure. Real parity is NOT established by the engineering tests.

Engineering tests use only n160 NumPy arrays, byte-only fake metadata source and
explicit fake tensor/call-counter objects. They never import Torch, load PT, read
public values/labels or run the formal generator. Fake object counts are unit
coverage, not evidence that a real neural forward succeeded. Freeze code/tests/
example before the <=60s CPU-only engineering run, save actual OS/stdout/hash,
then obtain independent/root review before a separate real seven-unit L0 release.

After that limited L0, controlled detection still needs its own signed run/data/
coverage/evaluation protocol. A frozen source model's negative response limits
that transfer instance. This sidecar cannot certify weak-amplitude, Self/Cross
mechanisms, physical causality, robustness or innovation.
